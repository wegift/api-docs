This event is essential when using the async ordering mode if you need to take action when an order has completed processing. It's also useful if you want to feed ordering data into your system.

The event uses the [Standard Webhooks](https://www.standardwebhooks.com/) envelope. The event type is in `type`, always `order.completion.v2` for this event, so you can dispatch on it if your endpoint receives more than one event type. The order is in `data`, and `timestamp` indicates when the event occurred.

The order payload depends on whether the order was processed successfully or not. You should use the `data.status` field to determine the type of payload you have received.

- Successfully completed orders will have a `status` of `COMPLETED`
- Failed orders will have a `status` of `FAILED`

The completed order event does not include the `items` field. Use the [get order](/reference/2024-02-05/endpoint/orders/get) endpoint if you need the order items.
